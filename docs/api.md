# REST API

The server exposes one JSON API under `/api/v1`. The web UI, the CLI, the desktop
client and the mobile apps all use it. Paths are defined once in
`crates/stickpile-api/src/routes.rs` and request/response types in
`crates/stickpile-api/src/model.rs`, so clients and server cannot drift.

The machine-readable description is served at **`/api/v1/openapi.json`**
(OpenAPI 3.1, generated from the handlers; no authentication needed). This page
explains the conventions and adds the notes the schema cannot express.

Conventions:

- JSON bodies (`Content-Type: application/json`) unless noted (uploads and
  imports are `multipart/form-data`).
- Timestamps are unix seconds (`i64`). IDs are opaque 26-character lowercase
  base32 strings generated by the server.
- Request bodies of ordinary endpoints are limited to 2 MiB; upload and import
  requests to `limits.max_request_mb` (see [configuration.md](configuration.md)).
- `GET /healthz` returns `{"status": "ok", "version": "..."}` without
  authentication.

## Authentication

Every `/api/v1` route needs an authenticated caller except
`POST /api/v1/auth/token`, `POST /api/v1/auth/register`,
`GET /api/v1/openapi.json` and the git webhook. There are three ways to
authenticate:

| Method | How | Typical client |
|---|---|---|
| Bearer token | `Authorization: Bearer spk_...` | CLI, desktop, mobile, scripts |
| Tailnet identity | `Tailscale-User-Login` header added by `tailscale serve`, trusted only on the proxy listener | browsers and clients on the tailnet |
| Session cookie | `stickpile_session` cookie set by the web UI login | web UI |

**Tokens** are created with a password (+TOTP) login,
`POST /api/v1/auth/token` (`TokenRequest` -> `TokenCreated`), or by an
already authenticated caller with `POST /api/v1/tokens`. The secret
(`spk_` + 52 base32 characters) is returned once; the server stores only its
sha256. Tokens can have an expiry and are revoked with
`DELETE /api/v1/tokens/{id}`.

**Tailnet identity** is only read from requests that arrive through the
trusted unix socket (`trusted_proxy.socket`) or over TCP from a loopback
address with the shared secret header (`trusted_proxy.secret_file`). On every
other request the `Tailscale-User-*` headers are ignored. See
[security.md](security.md#tailscale-trust-model).

**Precedence**: bearer > tailnet identity > session cookie.

- If an `Authorization` header is present it is the only credential
  considered. An unknown, expired or revoked token, or a scheme other than
  `Bearer`, is a `401` with no fallback.
- A tailnet login that maps to no user (and auto-create is off) counts as no
  identity, and the session cookie is tried next. A login bound to a disabled
  user is a `401`.
- Disabled users cannot authenticate in any way.

### CSRF

| Caller | Unsafe requests (POST, PUT, PATCH, DELETE) need |
|---|---|
| Session cookie | `X-CSRF-Token: <session token>` (or a `csrf_token` field in an `application/x-www-form-urlencoded` body of at most 64 KiB) **and** the same-origin check |
| Tailnet identity | the same-origin check |
| Bearer token | nothing (no ambient credential) |

The same-origin check rejects requests with `Sec-Fetch-Site: cross-site` or
`same-site`, an `Origin` of `null`, or an `Origin` that matches neither
`server.public_url` nor the request's `Host`. Requests without `Origin` and
`Sec-Fetch-Site` (non-browser clients) pass. Tailnet identity is attached by
the proxy to every request from the device, including a form a malicious site
submits, which is why it gets the same-origin check. Failures are `403` with
code `csrf`.

## Errors

Every non-2xx response has an `ApiError` body:

```json
{"code": "not_found", "message": "not found"}
```

| Code | Status | Meaning |
|---|---|---|
| `unauthorized` | 401 | No or invalid credentials |
| `totp_required` | 401 | Password correct, TOTP code required (`POST /auth/token`) |
| `forbidden` | 403 | Authenticated but not allowed (admin routes, edits of others' visible sets, closed registration) |
| `csrf` | 403 | CSRF token or same-origin check failed |
| `not_found` | 404 | Unknown, or not visible to the caller |
| `method_not_allowed` | 405 | Wrong method for the path |
| `bad_request` | 400/422 | Invalid input |
| `conflict` | 409 | Slug/username taken, last admin, already enabled, ... |
| `too_large` | 413 | File or request over the limit |
| `unsupported_media` | 415 | Not an accepted media type (after content sniffing), corrupt file, or a non-JSON body |
| `rate_limited` | 429 | Too many requests; `Retry-After` gives the seconds to wait |
| `internal` | 500 | Server error (details only in the server log) |
| `unavailable` | 503 | AI enrichment is off or the model is still loading |

Content the caller may not read (other users' private sets, their items and
files, jobs of other users) is reported as `404`, never `403`, so IDs cannot be
probed. A `403` only appears where the caller can already see the object
(editing someone else's public or unlisted set) or on admin routes.

## Pagination

- **`GET /api/v1/items`** (client cache sync): items ordered by
  (`updated_at`, `id`). Pass `next_cursor` as `cursor` for the next page
  (`limit` default 500, max 2000). `updated_since` is inclusive (`>=`), so
  changes in the same second are never missed; duplicates are harmless upserts.
  Store `server_time` and pass it as `updated_since` next time.
- **`GET /api/v1/admin/audit`**: newest first; pass the smallest `id` you have
  as `before` (`limit` default 100, max 1000).

`ItemPage.removed` lists items the caller could see before and can no longer
see. It is only filled when `updated_since` is given, and only on the first
page (no `cursor`). Removals are recorded as tombstones with an audience:

| Event | Owner learns | Other users learn |
|---|---|---|
| Item deleted, or its set deleted, while the set was public | yes | yes |
| Same, set private or unlisted | yes | no |
| Public set made private/unlisted, or item moved from a public to a non-public set | no | yes |

When a set becomes public again its tombstones for other users are dropped and
its items reappear in `items`. Tombstones are purged after 180 days; a client
that has not synced for that long should resync from scratch. Changes of a
set's name, slug or visibility and new variants bump `updated_at` of its items.

## Endpoints

`{id}` segments are 26-character IDs. Status `200` unless noted.

### Auth and tokens

| Method and path | Body -> response | Notes |
|---|---|---|
| `POST /api/v1/auth/token` | `TokenRequest` -> `TokenCreated` | Password login for API clients. `401 totp_required` if the account has TOTP and no code was sent. Rate limited per IP and per username. |
| `POST /api/v1/auth/register` | `RegisterRequest` -> `User` (201) | Policy `auth.registration`: `closed` -> 403; `invite` -> `invite_code` required, the account gets the invitation's role, codes are single-use; `open` -> role `user`. Usernames: 2-32 of `A-Za-z0-9_.-`, starting alphanumeric; passwords at least 8 characters. Rate limited like login. |
| `GET /api/v1/me` | -> `User` | |
| `PATCH /api/v1/me` | `UpdateMe` -> `User` | `username` (2-32 of `A-Z a-z 0-9 _ . -`, starting with a letter or digit; taken ignoring case -> 409; a change of case is allowed), `display_name` (empty resets it to the username), `telegram_user_id` (owner of exported Telegram packs; positive; `null` clears). Absent fields stay; every field is validated before anything changes. A rename keeps sessions, tokens and the tailnet login (they are bound to the user id), takes a display name equal to the old username along, refreshes the `by:` search and touches the user's items so clients refetch them (`updated_since`). The old name becomes free for others. Audited as `user.update_self` with `username: {from, to}`. |
| `PUT /api/v1/me/password` | `ChangePassword` -> 204 | `current_password` required if the account has one, unless the request is signed in through the tailnet (`tailscale serve` has just vouched for the person). At least `auth.min_password_length` characters (default 8). Other web sessions of the user are revoked; API tokens are kept. |
| `POST /api/v1/me/totp` | -> `TotpSetup` | Starts enrolment (secret + `otpauth://` URL); 409 if TOTP is already on. |
| `POST /api/v1/me/totp/confirm` | `TotpCode` -> `User` | Enables TOTP with a current code. |
| `POST /api/v1/me/totp/disable` | `TotpCode` -> `User` | Needs a current code. |
| `GET /api/v1/tokens` | -> `[ApiToken]` | The caller's tokens (never the secrets). |
| `POST /api/v1/tokens` | `CreateToken` -> `TokenCreated` | Optional `expires_at` (must be in the future). |
| `DELETE /api/v1/tokens/{id}` | -> 204 | Revoke. Someone else's token -> 404. |

TOTP: SHA-1, 6 digits, 30 s steps, one step of clock skew either way. A code
(step) is accepted only once.

| `POST /api/v1/sets/gitpack` | `CreateGitPack` -> `GitPackCreated` (201) | Bind a new set to a git repository; the clone runs as a `git_pull` job. See [git-packs.md](git-packs.md). |
| `POST /api/v1/sets/{id}/pull` | -> `Job` | Owner only (read-only packs included); a queued pull is reused. 400 if the set is not a git pack. |
| `POST /api/v1/hooks/git/{id}` | raw body -> `Job` (202) | **Unauthenticated** forge webhook: `X-Stickpile-Webhook-Secret` or `X-Gitlab-Token` with the secret, or `X-Hub-Signature-256` (HMAC-SHA256 of the body). 401 without, 403 with a wrong secret or signature, 404 for an unknown set or one that is not a git pack, 429 over 60 calls per minute per client IP. |
| `POST /api/v1/sets/{id}/telegram/export` | `TelegramExport` -> `Job` | Owner only. 400 for a bad pack name/title or when the caller has no Telegram user id and `telegram.default_owner_user_id` is unset. See [telegram.md](telegram.md). |
| `POST /api/v1/telegram/import` | `TelegramImport` -> `Job` | Into a new set; 409 if the slug is taken; counts as an upload for rate limiting. |

With `git.enabled = false`, the three git endpoints answer `404`. If
Telegram is not configured (`telegram.enabled` and a readable token file),
the two Telegram endpoints do the same. Every content or metadata change
bumps the set's `version`, and for push-mode git packs it also schedules a
push. Read-only git packs refuse every edit with `403` (`editable: false`).

**Uploads** (`POST /api/v1/sets/{id}/items`), owner only:

- Every multipart part with a filename is a file. An optional part named
  `meta` holds a JSON array of `UploadMeta`, matched to the files by index.
- Limits: each file at most `limits.max_upload_mb`, the whole request at most
  `limits.max_request_mb` (413 `too_large`). Each request counts once against
  `limits.upload_per_minute` (429).
- The type comes from the file content, never from the name: PNG bytes named
  `.gif` are stored as PNG; anything that is not PNG, JPEG, WebP, GIF, MP4 or
  WebM is 415 `unsupported_media`. Files are validated, sanitised and
  re-encoded; see [media.md](media.md).
- If one file was uploaded and it fails, the response is that error (413, 415,
  ...). With several files the response is 200 and failed files have `error`
  set and no `item`.
- Content is deduplicated by the sha256 of the uploaded bytes (or of a stored
  original, so re-uploading an export matches). The same content already in
  the set gives `already_in_set: true` and the existing item; in another set it
  creates a new item sharing the stored media.
- The item is appended to the set. `name` defaults to the filename without
  ordering prefix and extension (`001-cat.png` -> `cat`); `filename` is the
  slugified export stem.
- `near_duplicates` lists items **of the caller's own library** whose
  perceptual hash is within `media.near_duplicate_distance` (the same content
  in another set has `same_content: true`, distance 0). Other users' items are
  never reported.
- The thumbnail is stored immediately; other variants are generated by a
  background `Variants` job, and AI fields by an `Enrich` job when AI is on.

**Import** (`POST /api/v1/sets/import`) takes either a `set.toml` part (by
field name or filename) plus file parts whose filename is the path relative to
the set directory (one leading directory allowed), or a single `archive` part
holding a tar. The format is described in [set-format.md](set-format.md).

- Without `into`: creates a new set. The slug comes from `set.toml`'s `slug`
  or the slugified name; a slug the caller already uses is 409. The set gets
  the manifest's `version`, metadata, AI source markers and unknown keys.
- With `?into=<own set id>`: makes that set equal to the directory. Files are
  matched by sha256; matching items get the manifest metadata (`updated`, or
  `unchanged`), new files are added (`created`), items missing from the
  directory are removed (`removed`), and the order follows the filenames. If
  anything changed, `version` becomes `max(old + 1, manifest version)`.
- Per-file problems (unsupported type, too large, duplicate content) are listed
  in `errors`; the import continues.

**Export** returns `<slug>/set.toml` plus the stored originals named
`001-<stem>.<ext>`. Importing an export into a new set and exporting it again
gives the same manifest data and byte-identical files.

### Items

| Method and path | Body -> response | Notes |
|---|---|---|
| `GET /api/v1/items?updated_since=&cursor=&limit=` | -> `ItemPage` | Own and public items, never others' unlisted. See [Pagination](#pagination). |
| `GET /api/v1/items/{id}` | -> `ItemDetail` | Quality report, near-duplicates from the caller's library, apps that cannot take any current variant. |
| `PATCH /api/v1/items/{id}` | `UpdateItem` -> `Item` | Owner only. Edited fields become `user`-sourced; `confirm` (`name`, `keywords`, `emojis`, `vibe`) marks AI values as confirmed without changing them; `set_id` moves the item to the end of another set the caller can edit (409 if that set has the same media). |
| `DELETE /api/v1/items/{id}` | -> 204 | Owner only. |
| `GET /api/v1/items/{id}/file/{variant}` | -> bytes | See below. |
| `PUT /api/v1/items/{id}/like` | -> `LikeState` | Idempotent; allowed on every item the caller can read. |
| `DELETE /api/v1/items/{id}/like` | -> `LikeState` | Idempotent. |
| `GET /api/v1/items/{id}/better` | -> `[ItemSummary]` | Searchable items (own + public) with a pHash within the near-duplicate distance and a higher quality score, best first. |
| `POST /api/v1/items/{id}/enrich` | -> `Job` | Owner only; re-runs AI enrichment. 503 `unavailable` when AI is off or still loading. |

**Files**: `{variant}` is one of `original`, `thumb`, `png`, `tg_sticker`,
`tg_video_sticker`, `discord_gif`, `mp4`. A variant that does not exist (yet)
is 404. Responses carry the variant's `Content-Type`,
`X-Content-Type-Options: nosniff`, `Content-Disposition: inline;
filename="<stem>.<ext>"` (`<stem>-<variant>.<ext>` for non-originals), a strong
`ETag` (sha256 of the file) and `Cache-Control: private, max-age=31536000,
immutable`. `If-None-Match` gives 304; `HEAD` and `Range` requests are
supported.

### Search, usage and stats

| Method and path | Body -> response | Notes |
|---|---|---|
| `GET /api/v1/search?q=&limit=&offset=&target=` | -> `SearchResults` | Syntax in [search.md](search.md). Searches own and public items only. `limit` default 50, capped at 200; `q` at most 1000 bytes. With `target` (`telegram`, `discord`, `signal`, `whatsapp`, `slack`, `generic`) each hit gets `incompatible` when no current variant fits that app; unknown targets are 400. `semantic` is false when AI is off or not loaded yet. |
| `POST /api/v1/usage` | `UsageBatch` -> `UsageAck` | At most 1000 events. Idempotent by event `id` (1-64 of `A-Za-z0-9_-`); repeats count as `duplicates`. Events for unknown items, items the caller cannot read, or malformed ids are listed in `rejected`. `copied_at` is clamped to [now - 1 year, now + 1 day]. |
| `GET /api/v1/popular?scope=&set=&window=&limit=` | -> `Popular` | See below. |
| `GET /api/v1/stats/me` | -> `UserStats` | The caller's own numbers. `likes_received` excludes own likes; `daily_copies` has 30 UTC days, oldest first. |
| `GET /api/v1/profiles` | -> `[TargetProfile]` | What each chat app accepts. |
| `GET /api/v1/jobs/{id}` | -> `Job` | Only the job's owner or an admin; otherwise 404. |

**Popular** returns three lists that are never blended (`limit` per list,
default 20, max 100):

- `scope`: `server` (default; own items and public items), `mine` (items in
  the caller's sets, counting everyone's copies and likes), or `set` with
  `set=<id>` (any set the caller can read; others' private sets are 404).
- `most_copied`: copy events in `window` (`day`, `week` default, `month`,
  `all`); `value` = copies.
- `most_liked`: all-time likes; `value` = likes.
- `trending`: `c7` = copies in the last 7 days, `c28` = copies in the 28 days
  before. An item trends when `c7 > c28 / 4`; ordered by
  `(c7 + 2) / (c28 / 4 + 2)`; `value` = `c7`.

## Jobs

Background work runs in a database-backed queue with `media.workers`
workers. Failed jobs are retried with exponential backoff (10 s, 20 s) up to
3 attempts; permanent errors fail at once. Finished jobs are deleted after 30
days. `Job.result` is kind-specific:

| Kind | Queued by | `result` |
|---|---|---|
| `variants` | uploads, imports, restores | `{"variants": [...]}` |
| `enrich` | uploads, `POST /items/{id}/enrich`, AI start-up | model, keywords, emojis, vibe, items updated |
| `git_pull` | binding, `POST /sets/{id}/pull`, webhook, scheduler | `commit`, `changed`; after an import also `version`, `created`, `updated`, `unchanged`, `removed`, `errors`; `pushed` when local edits were pushed instead |
| `git_push` | every change of a push-mode pack (debounced 5 s) | `pushed`, `committed`, `commit`, `version`, or `skipped` |
| `telegram_import` | `POST /telegram/import` | `set_id`, `slug`, `pack_name`, `url`, `imported`, `skipped`, `bound` |
| `telegram_export` | `POST /sets/{id}/telegram/export` | `pack_name`, `url` (`https://t.me/addstickers/…`), `created_pack`, `added`, `removed`, `updated`, `reordered`, `exported`, `skipped` |
